# Static Tech Blog (knowledgebase) — Design Spec

Date: 2026-10-22
Repo: `TranChucThien/knowledgebase` (local: `~/DevOps/knowledgebase`)
URL: `https://tranchucthien.github.io/knowledgebase/` (GitHub Pages project site, no custom domain)

## Goal

A personal technical blog. Posts are Markdown files committed to the repo.
Posts are grouped and discoverable by tags and search. Every push to `main`
redeploys the site to GitHub Pages automatically.

The site is a **pure static web app**: plain HTML/CSS/JS, Markdown rendered
in the browser. No static-site generator, no npm dependencies, no bundler.
The only build step is a zero-dependency Node script that generates the post
index.

## Decisions

| Topic | Decision |
|---|---|
| Rendering | Client-side: browser fetches `.md` and renders it with `marked` |
| Routing | Hash routing (`#/...`), single `index.html` |
| Index | `posts.json` generated by `scripts/build-index.mjs` (Node 20, built-ins only) |
| Libraries | From cdnjs/jsdelivr, exact pinned versions: `marked`, `DOMPurify`, `highlight.js`, `Fuse.js` |
| UI language | English |
| Visual style | Developer / terminal-inspired: monospace, dark-first, prompt-style header |
| Hosting | GitHub Pages via GitHub Actions (`actions/deploy-pages`) |
| Paths | All asset/fetch paths relative, so the site works under `/knowledgebase/` or at a domain root |

Accepted trade-offs: weaker SEO (content appears after JS runs), URLs contain `#`.

## Content model

`posts/<slug>/index.md`; the folder name is the slug and the URL id.

```yaml
---
title: "Post title"
date: 2026-10-22
tags: ["kubernetes", "networking"]
summary: "One-sentence summary shown in lists and search results."
draft: false
---
```

- Supported front-matter subset (parsed by our own code, no YAML library):
  `key: value` strings (quoted or unquoted), and inline arrays `["a", "b"]`.
  Unsupported syntax makes the build script fail with the file name and line.
- Required: `title`, `date` (`YYYY-MM-DD`). Missing/invalid → build fails with a clear message.
- `tags`: lowercase kebab-case; build script normalizes to lowercase and trims.
- `summary` optional; defaults to the first ~160 chars of plain-text body.
- `draft: true` posts are excluded from `posts.json` unless `--drafts` is passed.

## `posts.json` (generated)

```json
{
  "generated": "2026-10-22T10:00:00Z",
  "posts": [
    {
      "slug": "k8s-networking",
      "title": "...",
      "date": "2026-10-22",
      "tags": ["kubernetes", "networking"],
      "summary": "...",
      "readingMinutes": 7,
      "text": "plain-text body for search (markdown syntax stripped)"
    }
  ]
}
```

Sorted by date descending. Tag counts are computed client-side from this list.

`build-index.mjs` also writes `feed.xml` (RSS 2.0, latest 20 posts, links to `#/posts/<slug>` under the site URL passed via `--site-url`, default `https://tranchucthien.github.io/knowledgebase/`).

## Routes

| Hash | Page |
|---|---|
| `#/` (or empty) | Home: prompt-style intro, latest 10 posts, top tags |
| `#/posts` | All posts grouped by year |
| `#/posts/<slug>` | Post: title, date, reading time, tags, auto TOC (h2/h3), content, prev/next |
| `#/tags` | All tags sorted by count, `#tag (n)` |
| `#/tags/<tag>` | Posts with that tag |
| `#/search?q=<query>` | Search box + live results; `q` kept in the hash so results are linkable |
| `#/about` | Renders `about.md` |
| anything else | "command not found" 404 view |

Router listens to `hashchange`, sets `document.title`, scrolls to top. In-page
heading anchors use `#/posts/<slug>?h=<heading-id>` so they don't collide with routing.

## Rendering pipeline (post page)

1. Look up slug in `posts.json`; unknown slug → 404 view.
2. `fetch('posts/<slug>/index.md')`; network error → inline error message with retry link.
3. Strip front matter, render with `marked`.
4. Rewrite relative image/link URLs to `posts/<slug>/...`.
5. Sanitize with `DOMPurify`, insert into DOM.
6. `highlight.js` on code blocks, add copy buttons, add heading ids, build TOC.

## Search

Fuse.js over `posts.json` with weighted keys: `title` (3), `tags` (2), `summary` (1.5), `text` (1).
Results show title, date, tags, summary. Typing updates the hash (`replaceState`, debounced).
A tag-prefixed query `#docker` filters by tag exactly.

## Visual style

- Font: `"JetBrains Mono", ui-monospace, SFMono-Regular, Menlo, Consolas, monospace` (JetBrains Mono via Google Fonts).
- Colors as CSS custom properties; dark default, light available. Toggle saved in `localStorage` (try/catch), fallback `prefers-color-scheme`. highlight.js dark/light themes switch with it.
- Header: `tranchucthien@kb:~$` + nav `posts`, `tags`, `search`, `about`, theme toggle.
- Tags as `#tag` in accent color. Content width ~72ch. Mobile: no horizontal page scroll; code blocks scroll internally.

## Deployment (`.github/workflows/deploy.yml`)

- Triggers: push to `main`, `workflow_dispatch`.
- Steps: checkout → `actions/setup-node` (20) → `node scripts/build-index.mjs` → copy `index.html`, `assets/`, `posts/`, `about.md`, `posts.json`, `feed.xml`, `.nojekyll` into `_site/` → `actions/upload-pages-artifact` → `actions/deploy-pages`.
- Permissions: `contents: read`, `pages: write`, `id-token: write`; concurrency group `pages`.
- One-time manual step: repo Settings → Pages → Source = "GitHub Actions".
- Build fails (and nothing deploys) if any post has invalid front matter.

## Local workflow

```bash
node scripts/new-post.mjs "My post title" --tags docker,linux   # scaffold
node scripts/build-index.mjs --drafts                            # regenerate index
python3 -m http.server 8000                                      # http://localhost:8000
```

## Seed content

3 sample posts with overlapping tags, code blocks in several languages, h2/h3 headings, one image; `about.md` placeholder.

## Testing / verification

1. `node --test scripts/` unit tests for front-matter parsing, validation errors, draft filtering, sorting, plain-text extraction.
2. Run the build script on seed content; check `posts.json` shape.
3. Serve locally and check with Playwright: home, posts list, post page (TOC, highlighting, copy button, image), tags index, tag page, search (typing, `?q=` reload, `#tag` filter), theme toggle persistence, 404, mobile width (375px), no console errors.

## Out of scope (later)

Comments (Giscus), analytics, pre-rendering for SEO, custom domain, linking from the GitHub profile README.
